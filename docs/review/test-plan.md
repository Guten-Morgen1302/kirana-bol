## Affected Pages/Routes
- POST /api/transcribe: audio in, transcript out; check all problem+json codes (RATE_LIMITED, DAILY_CAP, UPSTREAM_ERROR, BAD_AUDIO, EMPTY_AUDIO, SERVER_MISCONFIGURED) and that the key never appears in a response or log.
- POST /api/order: audio in, bill out; check the clarification turn state (kept client-side), the "not understood" list and the empty-transcript message.
- Demo page (single page): record, upload fallback, bundled sample-audio button (client-side only), quota-reached state, disabled-while-pending, latest-request-wins.
- Deployed URL (single always-on Node process): public transcription smoke test, cold-start warm-up, rate limit and daily cap hold across requests.

## Key Interactions to Verify
- Record a Hinglish order on desktop Chrome and on the phone browser used for the demo video; confirm the resampled 16 kHz mono WAV transcribes.
- Mic denied: instruction text plus file-upload fallback works.
- TTS readback: starts from a click handler, mic is disabled while it plays, a failed TTS shows the text bill with a notice.
- Clarification: first ambiguous item asked, answer matched only against candidates, unmatched or silent answer becomes "not understood".

## Edge Cases
- Trailing quantity phrase "woh Maggi wala packet, do" gives Maggi x2.
  Value: protects=trailing quantity binds to preceding item; fails_when=binder takes the next item or drops the quantity; why_new=no parser tests exist (greenfield); seam=none; no_claim=STT accuracy (written text only)
- Multi-item order "ek kilo chawal do Maggi": ek kilo binds to chawal, do binds to Maggi.
  Value: protects=following-item binding precedence; fails_when=do binds to chawal; why_new=greenfield; seam=none; no_claim=STT accuracy
- Unit mismatch "kilo Maggi" is flagged and defaults to 1 packet; repeated item mentions sum quantities.
  Value: protects=unit-fit and repeat rules; fails_when=quantity lost or doubled; why_new=greenfield; seam=none; no_claim=STT accuracy
- Fuzzy thresholds inclusive at 0.80 and 0.65; tokens shorter than 4 characters match exactly only; Unicode NFC and nukta variants normalize equal.
  Value: protects=no false positives on short Hindi number words; fails_when="do" fuzzy-matches an item alias; why_new=greenfield; seam=none; no_claim=real transcripts (see pilot transcripts test)
- Parser run on the real Nov 6 pilot transcripts (not only written text): at least the same gate (18 of 20 style) on STT-like mistakes.
  Value: protects=parser works on real STT output; fails_when=pilot transcripts parse worse than written text by more than 20 points; why_new=written-text gate says little about STT noise; seam=none; no_claim=other speakers or noise levels
- Scoring: not-understood counts as missed; defaulted quantity correct only if truth is 1; F1 micro-averaged per level; WER only when script rules agree between models.
  Value: protects=headline metric correctness; fails_when=an unmatched item is counted correct; why_new=greenfield; seam=none; no_claim=model quality
- Noise mixing: measured SNR of a mixed clip is within 0.5 dB of the target; noise is added before the telephony codec; same seed gives the same mix.
  Value: protects=levels mean what the table says; fails_when=mix level drifts; why_new=checksum test was withdrawn so this is the only guard; seam=none; no_claim=real-world noise realism
- Bench resume: a rerun skips successful clips, retries failed clips, results.json is written atomically (temp file then rename); a forced failure exits non-zero.
  Value: protects=no double spend and no corrupt results; fails_when=successful clip is resent or file truncated; why_new=greenfield; seam=none; no_claim=API behavior (mocked)
- Proxy with mocked upstream: timeout, 429, 5xx, malformed JSON, empty transcript, huge transcript, Devanagari-only output; retries use 500 ms and 1500 ms backoff and only for 429 and 5xx; body size limit rejects before buffering.
  Value: protects=error contract and credit safety; fails_when=failure returned as 200 or key echoed; why_new=greenfield; seam=none; no_claim=real provider acceptance (mocked provider)
- Rate limit and daily cap on the deployed single process: the 31st call in a minute from one IP gets 429 with Retry-After; global daily cap refuses before the upstream call; client IP taken only from the platform's trusted header.
  Value: protects=credits cannot be drained; fails_when=cap not enforced across requests; why_new=in-memory counters fail on serverless, so the host choice is tested; seam=none; no_claim=multi-instance behavior (single process by design)
