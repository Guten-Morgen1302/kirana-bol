## Approaches Considered
### Approach A: Web app, mic in, live bill, voice readback (recommended)
Browser records audio and sends it to a thin server-side proxy (a small Node or Python route, deployed with the app) that calls Prisma and Timbre, so keys never reach the browser. API mode (streaming vs batch upload) is UNVERIFIED until the gating check in Next Steps; the design works in batch mode (record, stop, transcribe) and upgrades to streaming only if the docs show browser-friendly WebSocket support. Effort: M, roughly 3 working days for one person plus 1 day for video and post. Risk: Medium. Reuses nothing (empty repo).

**Parser (deterministic, no LLM).** Catalog of 40 items, each with aliases in romanized Hinglish and Devanagari (for example chawal/rice/चावल; Maggi/maggi/मैगी). Steps: lowercase and strip punctuation; map Hindi number words and digits to numbers (ek=1, do=2, teen=3, aadha=0.5, dedh=1.5, dhai=2.5); detect units (kilo, kg, gram, packet, litre, dozen); match item tokens to aliases by fuzzy ratio with threshold 0.80; bind the nearest quantity-plus-unit to the matched item. Acceptance gate: at least 18 of 20 written test utterances parse to the exact expected order on clean text before any audio work is trusted.

**Dialog behavior.** Exactly one clarification turn per order. If an item scores 0.65 to 0.80, or an alias maps to several catalog items (Maggi masala vs Maggi atta), Timbre asks one question and the next recording is matched only against those candidates. If several items in one order are ambiguous, ask about the FIRST ambiguous item only (in spoken order) and mark every other ambiguous item "not understood". If the clarification answer matches none of the candidates, or is empty or silent, that item becomes "not understood" and no further turn is taken. Below 0.65 the item is listed as "not understood" on screen and skipped, with no second question. Empty or silent transcript: show "kuch suna nahi, phir boliye" and keep the bill unchanged. Missing quantity defaults to 1 unit and is flagged.

**Noise benchmark method.** 30 invented orders (text), each spoken once by the builder in a quiet room (30 clean clips, ground-truth order written beforehand). Each clip goes through a telephony simulation (resample to 8 kHz narrowband, then encode and decode with a lossy codec such as AMR-NB or G.711 via ffmpeg), and is mixed with a royalty-free street/shop ambience bed (self-picked from a free sound library, source and licence noted in the repo) at three levels: clean, 10 dB SNR ("street"), 0 dB SNR ("loud shop"), giving 90 clips. The evidence is described honestly as SIMULATED telephonic noise, not real calls (real calls are barred by the synthetic-data rule). Metric: item-level F1 (an item counts as correct only if item and quantity both match ground truth) plus word error rate on the transcript. Reported per level in a table on the benchmark page. Credit budget: 90 clips averaging 8 seconds is 12 minutes of audio, to be checked against the 5,000-credit price once known.
